# Waqt Web — Stitch design implementation report (v2)

Branch: `feature/stitch-web-design` · scope: `apps/web/`, one CI step, this report. Nothing merged into `main`.
v2 replaces my first pass, which used my own look instead of the Stitch export.

## 1. What the Stitch export was, and what I did with it
The zip held 10 pages of Tailwind-CDN HTML plus a design system ("Precision Astrometric Infrastructure": Space Grotesk /
Inter / JetBrains Mono, obsidian surfaces, cyan primary, amber secondary, 4 px radii, telemetry-panel micro-labels).
I **ported the design system, layouts and page structure faithfully** and **did not port its copy**, because much of it
is not true of this project. Examples I removed or replaced: "VSOP87D" as the production engine (it is
`waqt-noaa-low-precision`, accuracy level B; VSOP87/JPL DE421 are verification references), "RFC-0024 v0.4.1",
a `/v1/telemetry` endpoint, GraphQL/protobuf/WebSocket interfaces, `application/ld+json+waqt`, a Rust core and
0.12 ms benchmarks, watchOS/Wear OS apps, invented decision records, dates, hashes, stewards and working groups,
"Aqrab al-Bilad"/proportional high-latitude fallbacks (the API returns an explicit `UNDEFINED` and applies no
fallback). A test (`test_no_unsupported_stitch_claims_survive`) now fails if any such claim reappears.

## 2. Architecture
Static site, no server build, `render.yaml` unchanged. Tailwind is a **dev-time** step: `apps/web/tools`
compiles `assets/css/stitch.css` (17 KB) from the Stitch tokens; fonts are self-hosted (3 woff2, 110 KB); icons are
inline SVG; no CDN, no Google Fonts. Pages are generated by `tools/build_pages.py` so the shared header/footer cannot
drift (a test enforces identical navigation); generated HTML is committed. The original viewer is preserved as
`reference-viewer.html` with its inline script **byte-identical** to the original (tested against commit 1766ff3).

## 4. Real data vs concepts
**Real, from the API:** home viewport and telemetry, circular clock (reusable), mosque-clock and watch previews,
day-length measurement, midnight-vs-Waqt comparison, Live Demo (any place; Fajr/Isha angles, Asr ratio, Hijri
provider), How-It-Works probes (polar UNDEFINED, Fajr-angle invariance), Lab steps, API tester/status, version axes.
**Real, from the repository at build time:** the 8 decision records (titles, dates, requirements, status) and the
open-questions register (all unresolved items listed on Community). **Concept/Future:** every device or product
image; all carry a visible "Concept art" tag and CONCEPT/FUTURE badges.

## 5. Endpoints used
`/v1/waqt` (incl. `instant`, `fajr_angle`, `isha_angle`, `asr_ratio`, `calendar_provider`), `/v1/calendar`,
`/v1/version`, `/v1/health`, plus `/v1/day` and `/v1/events` through the API tester. Links to the API's own `/docs`
and `/openapi.json`. None invented (a test checks fetched paths).

## 6. Honest states
loading / success / empty (UNDEFINED shown with the server's reason) / error / offline. On error or offline the
page shows a frozen recorded sample stamped "DEMO · NOT LIVE" on the clock face and in the banner; it never ticks.

## 10. Remaining backend/API requirements
1. `/v1/waqt` `events` omits the current day's own Isha (lists the next evening's, reading ≈ 25:05); drawn as a dashed
   "after next Maghrib" marker rather than invented.
2. `WAQT_CORS_ORIGINS` must include the static site's origin on Render.
3. Free-plan cold starts can exceed a minute (25 s timeout, then labelled demo with auto-retry).
4. `conformance/MAINTAINERS.md` unfilled; DR-0001…0008 ratification pending — shown on Governance.

## 11. Preview
```
pip install -e ./core -e . -e ./local
WAQT_CORS_ORIGINS=http://localhost:8080 uvicorn waqt.api:app --port 8000
python -m http.server 8080 --directory apps/web
```
Rebuild after editing pages/classes: `cd apps/web/tools && npm install && python3 build_pages.py && npm run build:css`.
