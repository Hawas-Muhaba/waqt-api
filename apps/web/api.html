Build with the Waqt API

A versioned, language-independent HTTP contract. Every response is one envelope — {meta, data, error} — with exactly one of data and error set.

Endpoints

Waqt API endpoints
EndpointReturns
GET /v1/waqtEverything: day boundary, reading, six events, next event, Hijri date. Powers every live component on this site.
GET /v1/dayThe day boundary only.
GET /v1/eventsThe six events only (no calendar).
GET /v1/hijriCalendar lookup; no location needed.
GET /v1/calendarDiscovery: the available calendar providers.
GET /v1/locationTimezone and local civil-date resolution.
GET /v1/conversionsGregorian ↔ Hijri, either direction.
GET /v1/versionEvery version axis: spec, engine, API, conformance.
GET /v1/healthComponent status.
/v1/schedule/*Snapshot, span and rule resolution (windows, deadlines, “30 minutes before Maghrib”).
/v1/institutional/*Islamic week, fiscal year, academic year.

Schemas, error codes, units and versioning policy: docs/API.md in the repository.

Example

A complete call



day.maghrib_open / maghrib_close
Exact instants bounding the day; length_si_seconds is its real length.
waqt.reading
Seconds and HH:MM:SS since the opening Maghrib; may pass 24:00:00.
events[]
Fajr, sunrise, Dhuhr, Asr, Maghrib, Isha: an instant and a reading each.
next_event
The earliest event after instant, with a ready-made countdown.
status
OK, or an explicit UNDEFINED with a reason.
computation
Engine, accuracy level, timescale model and ΔT used.
