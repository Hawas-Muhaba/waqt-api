API

Build with the Waqt API

A stable, versioned, language-independent HTTP contract. You do not need to read any Python to integrate it. Every response is an envelope: {meta, data, error}, with exactly one of data and error non-null.

Endpoints

Waqt API endpoints
EndpointWhat it returns
GET /v1/waqtEverything: day boundary, clock reading, all six events, next event, Hijri date. Powers every live component on this site.
GET /v1/dayDay boundary only.
GET /v1/eventsThe six prayer/solar events only (no calendar).
GET /v1/hijriCalendar lookup, no location needed.
GET /v1/calendarDiscovery: which calendar providers exist.
GET /v1/locationTimezone and local civil-date resolution.
GET /v1/conversionsGregorian ↔ Hijri, either direction.
GET /v1/versionEvery version axis: waqt-core, engine and revision, API, conformance vectors.
/v1/schedule/*Snapshot, span and rule resolution (windows, deadlines, “30 minutes before Maghrib”).
/v1/institutional/*Islamic week, fiscal year, academic year.

Full request and response schemas, error codes, units and versioning policy are in the repository’s docs/API.md (see Resources).

A complete call


    
Reading the response

    

      
day.maghrib_open / maghrib_close
Exact instants bounding the Waqt day; length_si_seconds is its real length.

      
waqt.reading
Seconds and HH:MM:SS since the opening Maghrib. May pass 24:00:00 on a long day.

      
events[]
Fajr, sunrise, Dhuhr, Asr, Maghrib, Isha, each an instant plus its reading. An event after the closing Maghrib reads past the day length (Isha often does).

      
next_event
Earliest event strictly after instant, including the previous solar day’s Isha — with a ready-made countdown.

      
status
OK or an explicit undefined with a reason (e.g. polar regions). Never silently defaulted.

    

    
Rule of the house: consume Waqt, do not reimplement it. This website follows it — it contains no astronomy or calendar computation.
