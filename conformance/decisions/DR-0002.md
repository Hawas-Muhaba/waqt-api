## Context
Two choices were shared by both implementations and so could never be exposed by comparing them: which date an event after local midnight belongs to, and what happens to a day when exactly one of its bounding Maghribs is undefined.

## Decision
EVT-004: an event belongs to the Waqt day around its own upper transit, even if it falls after local midnight; listings do not move to the next civil date. UND-001: a day with exactly one undefined bounding Maghrib is wholly UNDEFINED (for example the last evening before polar day); no partial day is invented.

## Evidence
No difference observed in 300 random cases plus 33 oracle places (Sprint 15). Both implementations and the reference agree; SEMANTICS section 8 already implied the second rule.

## Consequences
Text only; no code or vector expectation changed. Requirement titles now state the rules.

## Alternatives considered
Moving after-midnight events to the next civil date: rejected, it would detach Isha from the Maghrib that precedes it.

## Configurability (religious / regional conventions)
Not configurable: this is bookkeeping, not a religious or regional convention. Polar-region *fallback* methods (e.g. nearest-latitude) are a separate, explicitly out-of-scope configurable question (SCOPE.md).

## Dissent and unresolved points
None.

## Reopen when
Evidence of a case where assigning by transit gives an event on the wrong Waqt day.
