## Context
Prior to API 1.7.0, provider-aware endpoints defaulted to `arithmetic-tabular` when `calendar_provider` was omitted. To align out-of-the-box behavior with Saudi civil conventions and the web application interface, the default provider was updated to `umm-al-qura`. Outside `umm-al-qura`'s validated supported range (`1700-01-01` to `2300-12-31`), calls fail with `CalendarOutOfRange`, returning HTTP 400 with error code `OUT_OF_RANGE`.

## Decision
1. `umm-al-qura` is established as the single default calendar provider across the HTTP API (1.7.0), local facade (`waqt_local`), CLI (`waqt_cli`), Web Application, and SDK defaults.
2. Callers may explicitly request `calendar_provider=arithmetic-tabular` (or any other catalog provider) at any time to preserve closed-form arithmetic behavior.
3. Provider requests for `umm-al-qura` outside `1700-01-01` .. `2300-12-31` return HTTP 400 with code `OUT_OF_RANGE` on direct calendar endpoints, and populate `calendar_error` while keeping astronomical events computed intact on `/v1/waqt`.

## Evidence
- Pinned and verified across unit, API, local facade, CLI, JS SDK, and independent conformance test suites (629+ tests passing).
- Verified on official table oracle tests (`hijridate==2.3.0`) over 913 days (2025-06-01 to 2027-11-30).

## Consequences
- Single unified default calendar provider across all surfaces (API, CLI, local library, web).
- Explicit error handling for dates outside Umm al-Qura's supported span without hiding underlying solar computation.
