## Context
Until API 1.6.0 a request that omitted `calendar_provider` was served by `arithmetic-tabular`. The project owners (Dr. Salim Muhammed Redi and Mr. Hawas Muhaba Hussein) chose Option B: the default becomes `umm-al-qura`.

## Decision
When `calendar_provider` is omitted, every provider-aware endpoint uses `umm-al-qura`; `calendar_provider=umm-al-qura` and `calendar_provider=arithmetic-tabular` keep selecting those providers; an unknown name stays `400 UNKNOWN_CALENDAR_PROVIDER`; every response names the provider actually used. The Hijri provider labels days only: Waqt days (Maghrib to Maghrib), event instants, positions and countdowns do not depend on it. Provider defaults may change only by a decision of the project owners, in a new API version, with a migration record, versioned vectors and instructions for preserving previous results (`docs/VERSIONING.md`).

## Evidence
`docs/migrations/API-1.7.0-default-provider.md` (11 recorded responses classified; none moved an astronomical value), `tests/test_default_provider_option_b.py` (every provider-aware route; 46 of its tests fail if the default is reverted), `verification/live_stack_check.py`, `verification/vector_additivity_check.py` (historical recordings reproduced byte-for-byte under their declared provider). **Not measured:** how many external clients consumed API 1.7.0 before this record (the repository carries no tags and no usage data).

## Consequences
A behaviour change within `/v1`, not a shape change; one additive field (`calendar_provider`) on six response shapes. Highest-risk effect: `GET /v1/conversions?direction=to-gregorian&year=1448&month=4&day=7` returns 2026-09-18 instead of 2026-09-20. Vectors: `sdk_conformance_vectors.json` is unchanged and is replayed under a declared migration; `sdk_conformance_vectors_api_1_7.json` records the new default. No conformance vector changes.

## Alternatives considered
(A) Keep `arithmetic-tabular` as the default: rejected by the owners. (C) Require the provider on every request: not chosen; it would break every existing caller.

## Configurability (religious / regional conventions)
Umm al-Qura is a deliberate project default, **not** a claim that every Muslim community follows one calendar convention. The provider stays selectable on every request (`arithmetic-tabular`, `declared`, `local-observation`, `aladhan`) and is always named in the response; Waqt Web states this on the page.

## Dissent and unresolved points
None recorded. Still open and not decided here: whether `waqt-core`'s internal fallback (`calendar_interop._DEFAULT_PROVIDER`, `ArithmeticTabularProvider`) should follow the API default; version bumps of `waqt-local` and `waqt-cli`, whose defaults now follow the API.

## Reopen when
The owners change the default again, or a requirement is added to the contract that fixes a default provider.

## Vectors affected
`sdks/vectors/sdk_conformance_vectors.json` (11 omitted-provider vectors, replayed under `verification/vector_migrations/api-1.6.0-to-1.7.0.json`); `sdks/vectors/sdk_conformance_vectors_api_1_7.json` (new).
